A [slider](/ditto/components/slider/) with a start and an end — a price band, a date window, a
duration between two bounds. It shares `SliderStyle`, so it matches the single-value slider beside
it without extra configuration.

<Demo id="range-slider" height={200} />

## Usage

```kotlin
var span by remember { mutableStateOf(0.2f..0.7f) }

RangeSlider(
  value = span,
  onValueChange = { span = it },
  valueRange = 0f..1f,
  onValueChangeFinished = { commit(span) },
)

// Snapped to quarters: steps counts the stops *between* the ends
RangeSlider(value = span, onValueChange = { span = it }, steps = 3)
```

## Behaviour

- Pressing the track grabs the **nearer** thumb and jumps it to the press, then drags from there.
- The thumbs cannot cross; each stops at the other.
- Stepped ranges track an unsnapped internal position, so a drag keeps moving instead of sticking
  to the stop it just snapped to.

Use `onValueChangeFinished` for work you do not want to run on every frame of a drag — a network
call, a database write.

## Keyboard

Each thumb is its own focus stop, because each is its own value — one conflated "range" node is
something assistive tech cannot address.

| Key | Action |
|---|---|
| ← / → | move the focused thumb (RTL-aware) |
| ↑ / ↓ | same, without the mirroring |
| Home / End | send it to its own limit — the range end, or the other thumb |

A step is `span / (steps + 1)` when stepped, and 5% otherwise.

## Accessibility

- Each thumb carries its own progress semantics **and its own `setProgress` action**, with bounds
  that stop at the other thumb, so either end can be set directly.
- The thumbs are labelled "Range start" and "Range end" rather than sharing one name.
- The container carries no name of its own: it would merge the two thumbs into a single node.

## API

```kotlin
@Composable
fun RangeSlider(
  value: ClosedFloatingPointRange<Float>,
  onValueChange: (ClosedFloatingPointRange<Float>) -> Unit,
  modifier: Modifier = Modifier,
  enabled: Boolean = true,
  valueRange: ClosedFloatingPointRange<Float> = 0f..1f,
  steps: Int = 0,
  onValueChangeFinished: (() -> Unit)? = null,
  style: SliderStyle? = null,
)
```
